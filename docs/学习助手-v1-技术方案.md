## 2. Manifest 与权限

```json
{
  "manifest_version": 3,
  "minimum_chrome_version": "116",
  "permissions": ["contextMenus", "sidePanel", "storage", "activeTab"],
  "optional_host_permissions": ["http://*/*", "https://*/*"],
  "background": { "service_worker": "background.js" },
  "side_panel": { "default_path": "sidepanel/index.html" },
  "options_page": "options/options.html"
}
```

**关键决策：host_permissions 怎么满足"API 域名最小化"**

文档要求「API 域名的 host_permissions、不申请 `<all_urls>`」。但 baseURL 是用户运行时配置的，manifest 无法预知域名。方案：

- manifest 声明 `optional_host_permissions`（`http://*/*` + `https://*/*`，仅声明不生效）
- 设置页保存 / 测试连接时，在用户手势内调用 `chrome.permissions.request({ origins: [origin + "/*"] })`，**只授予当前 baseURL 的精确 origin**
- 效果：安装时不占任何 host 权限；换服务商时按需追加；比 `<all_urls>` 更贴合最小化原则，也是 MV3 生态的标准做法

## 3. 核心数据流（SW → storage.session → 侧边栏）

```
网页：选中文字 → 右键「问 AI ▸ 预设」
        │ contextMenus.onClicked（用户手势，拿 info.selectionText / tab.title / tab.url）
        ▼
background.js（SW）
        │ ① 组装 task { taskId, type, template, vars }
        │ ② chrome.storage.session.set({ task })   ← 规避 SW 休眠丢消息
        │ ③ chrome.sidePanel.open({ tabId })
        ▼
chrome.storage.session（key: task）
        │ storage.session.onChanged + init 兜底读取（taskId 幂等去重）
        ▼
sidepanel.js（常驻页面）
        │ ① 占位符渲染 {{text}} {{title}} {{url}} {{lang}}
        │ ② 组装 messages（system + user）
        │ ③ fetch(baseURL → /chat/completions, stream: true, AbortController)
        ▼ / ▲
OpenAI 兼容 API（SSE delta 流式回传）
        │
        ▼
渲染管线：marked.parse → DOMPurify.sanitize → innerHTML
        （rAF 节流合并 delta；完成后 highlight.js 高亮代码块）
```

### 3.1 竞态坑：面板打开与存储事件的时序（重点）

右键点击时侧边栏通常是**关闭**的。`sidePanel.open()` 异步加载页面，若存储事件在面板 JS 注册监听器之前触发，任务就丢了。双保险：

1. **监听路径**：面板注册 `storage.session.onChanged`，实时接任务
2. **兜底路径**：面板 init 时主动 `storage.session.get('task')` 读一次
3. **幂等去重**：每个 task 带 `taskId`（crypto.randomUUID），面板记录已处理的 taskId，两条路径不会重复消费

### 3.2 storage.session 访问级别坑

`storage.session` 默认**只有 SW 可读**。必须在 SW 顶层（每次唤醒都会执行）调用：

```js
chrome.storage.session.setAccessLevel({ accessLevel: 'TRUSTED_AND_UNTRUSTED_CONTEXTS' });
```

否则侧边栏读不到任务，且没有任何报错提示。

## 4. 会话与多轮设计

### 4.1 thread 结构（内存 + storage.session，全局单条时间线）

```json
[
  { "role": "system",  "content": "你是学习助手…用户正在阅读《页面标题》(url)，选中文字：「…」" },
  { "role": "user",    "content": "用三句话说清「xxx」…（模板渲染结果）" },
  { "role": "assistant", "content": "…（流式答案）" }
]
```

- **每次右键任务**：push 一条新的 system（页面上下文 + 选区）+ user（渲染后模板）
- **底部追问**：直接 push user；发请求时取「最近一条 system + 最近 20 条 user/assistant」作上下文，连续追问不断片
- **多次右键**：同一条时间线里多组问答，追问上下文延续到最新一组
- **「自定义输入」菜单项**：面板聚焦输入框 + 显示选区 chip，首次发送时才注入 system 上下文
- **历史**：thread 序列化到 `storage.session`（浏览器重启自动清空，符合"仅会话内"），`maxHistory` 按 Q&A 对截断；`keepHistory: false` 时纯内存
- system 消息不展示在时间线上，仅进 API 上下文

### 4.2 system 上下文模板

```
你是一名学习助手，帮助用户在浏览网页时快速理解内容。用与用户提问相同的语言回答，简洁准确。
用户正在阅读的页面：《{title}》 {url}
用户选中的文字：「{text 截断至 2000 字}」
```

选区超长截断（超长选区本就该用"整页总结"，放后续版本）。

## 5. API 调用与流式

### 5.1 URL 归一化（一套通吃）

| 用户输入 | 实际请求 |
|---|---|
| `https://api.openai.com/v1` | `…/v1/chat/completions` |
| `https://api.deepseek.com` | `…/v1/chat/completions`（自动补 /v1） |
| `http://localhost:11434/v1`（Ollama） | `…/v1/chat/completions` |
| `https://xxx/one-api/openai` | `…/openai/v1/chat/completions` |
| 已以 `/chat/completions` 结尾 | 原样使用 |

规则：结尾已是 `/chat/completions` → 原样；路径含版本段（`/v1`、`/v2`、`/v1beta`）→ 只补 `/chat/completions`；否则补 `/v1/chat/completions`。设置页"测试连接"会展示解析后的最终 URL。

### 5.2 流式与中断

- SSE 解析：`res.body.getReader()` + TextDecoder 按行拆 `data:`；容忍 `:` keep-alive 注释行、空 `data:`、非 JSON 行（try/catch 跳过）
- 中断：UI 停止按钮 → `AbortController.abort()`，已收到的部分内容保留并标记"已停止"
- 超时：连接超时 30s（`setTimeout` + abort）；**拿到响应头后立刻清除定时器**，不杀长流式
- 非流式：`stream: false` 时直接解析完整 JSON

### 5.3 错误态映射（每条都给行动指引）

| 状态 | 提示 |
|---|---|
| 401 | API Key 无效或未授权 → 去设置页检查 apiKey |
| 404 | 接口路径不存在 → 检查 baseURL（通常以 /v1 结尾） |
| 429 | 请求过于频繁或额度不足，稍后再试 |
| 5xx | 服务端错误，可重试 |
| TimeoutError | 连接超时（30s 无响应头） |
| TypeError | 断网 / baseURL 不可达 / **该域名权限未授予**（保存设置时记得允许） |

每条错误卡片带「重试」按钮（复用上一条 user 消息重跑）。

### 5.4 Anthropic

v1 仅实现 OpenAI 兼容协议。保留钩子：URL 命中 `anthropic.com` 时自动附加 `anthropic-dangerous-direct-browser-access: true` 请求头；但 Anthropic 的报文格式（`/v1/messages`、`x-api-key`）不同，完整支持放后续版本的"多 API profile"。

## 6. 渲染管线

- **流式节流**：高频 delta 用 `requestAnimationFrame` 合并后整段重渲（单条回答体量下性能足够，避免增量 DOM 拼接的复杂度）
- **安全**：`marked.parse → DOMPurify.sanitize → innerHTML`，AI 输出同样不可信
- **高亮**：流式期间不做（省 CPU），完成后对 `pre code` 统一跑 `hljs.highlightElement`
- **代码块**：自动横向滚动 + 悬浮复制按钮
- **滚动**：自动跟随到底部；检测到用户手动上滚则暂停跟随，回到底部附近恢复
- **公式**：v1 不含（版本规划里公式也不在 v1 清单），v2 引 KaTeX 本地打包

## 7. 设置页

| 区块 | 内容 |
|---|---|
| API | baseURL（带 OpenAI/DeepSeek/Moonshot/通义/Ollama 快捷填充）、apiKey（密码框）、model（datalist 常用模型提示）、temperature 滑杆、stream 开关、测试连接 |
| 预设问题 | 列表：启用开关 / 标签 / 模板编辑（展开式）；拖拽排序；新增 / 删除；导入 / 导出 JSON（含格式校验，导入重新分配 id） |
| 界面 | sidebarScope（v1 固定 global，选项保留）、keepHistory、maxHistory |

- 数据单 key `settings` 存 `chrome.storage.local`，结构与需求文档的数据模型一致：

```json
{
  "api": { "baseURL": "", "apiKey": "", "model": "", "temperature": 0.3, "stream": true },
  "prompts": [
    { "id": "p1", "label": "三句话说清", "template": "用三句话说清「{{text}}」…", "order": 1, "enabled": true }
  ],
  "ui": { "sidebarScope": "global", "keepHistory": false, "maxHistory": 50 }
}
```

- SW 监听 `storage.onChanged`：prompts 变更 → 重建右键菜单（无需重启浏览器生效）
- apiKey 只进 local，绝不进 sync —— 符合文档约束

## 8. 坑位清单（实现时逐一核对）

1. **`sidePanel.open()` 需 Chrome 116+** 且必须在用户手势内调用（`contextMenus.onClicked` 算手势，OK）；`minimum_chrome_version` 写进 manifest
2. **storage.session 访问级别**：见 3.2，不设置则面板静默读不到
3. **selectionText 可能被截断**：右键菜单传入的选区文本存在长度上限的历史行为。v1 接受现状并在 README 标注；若实测影响大，v1.1 增加 `scripting` 权限用 `executeScript` 取完整选区（activeTab 在右键手势后已临时授权页面访问）
4. **无 host 权限时 fetch 被拦**，表现与"断网"相同 → 错误文案里必须提示"检查域名权限是否已授予"
5. **MV3 CSP 禁远程代码**：marked / DOMPurify / highlight.js 构建时下载到 libs/，运行时零外链
6. **SSE 容错**：个别网关夹注释行、空行、非标准 JSON，解析循环全部 try/catch
7. **菜单持久化**：contextMenus 注册在浏览器侧，SW 冷启动不需要重复注册；只在 onInstalled / prompts 变更时重建
8. **CSP 与内联脚本**：所有 JS 走外部文件引用，HTML 里零内联脚本/样式，避免 MV3 CSP 拒绝
